# Этап 4 — стенд анимаций

21.10.2026. Кандидат опубликован в main. Стенд находится в `web/animation-lab/`.
Он проигрывает контрольные математические книги, а не выбирает случайные исходы.
Ставок, баланса, запросов RGS и звука пока нет. Это промежуточная проверка
анимационного этапа, не готовый к отправке на платформу фронтенд.

## Запуск

Из корня репозитория:

```sh
python -m http.server 8765
```

Открыть http://localhost:8765/web/animation-lab/.
Сборщик и внешние библиотеки для воспроизведения не требуются: используются
нативные ES modules, CSS и Web Animations API. Это осознанный отдельный стенд,
а не утверждение об интеграции Svelte/PixiJS или официального Web SDK.

## Реализованные эффекты

- Вращение с motion-blur изображениями и остановкой с отскоком −10/+8 px.
- Задержка и зелёная рамка anticipation берутся из поля события, не выводятся
  из самостоятельно рассчитанного числа scatter.
- Выигрышные позиции увеличиваются до 112% дважды; линии рисуются по координатам
  из `winInfo`. Линии с нулевой начисленной выплатой не празднуются.
- Wild появляется снизу через маску ячейки; scatter покачивается на ±5°.
- Могилы темнеют и светятся; таблички ×2/×3/×5/×10 увеличиваются при обновлении.
- Вход, ретриггер и итоги бонуса, счётчик итогового выигрыша, Big/Mega/Epic Win,
  переключение поз Мортимера и частицы.
- Плавный туман, idle персонажа, периодический пролёт летучей мыши.
- Мортимер закреплён на отдельном слое каменистой земли. Контактные тени
  соответствуют каждой из трёх поз; дыхание растягивает спрайт вверх от подошв,
  сохраняя опору. В портретной компоновке земля и ноги видны над нижней панелью.
- Все длительности заданы в `TIMINGS`. Турбо ×3 ускоряет эффекты; локальный
  переключатель запрета турбо отключает ускорение. Для этапа 6 нужно подключить
  настоящий флаг jurisdiction из authenticate к тому же ограничению.
- Системная настройка reduced motion и отдельный переключатель отключают движение.
- Любой длинный эффект можно пропустить кликом по сцене, пробелом или кнопкой.
  «К итогу» ускоряет оставшиеся эффекты, сохраняя обработку каждого события.

Плашки выигрышей показываются только для начисленного итога выше стоимости
режима и от 20 общих ставок. Это только политика визуального празднования;
результат и суммы всегда берутся из книги, расчёта выплат здесь нет.

## Архитектура и восстановление

`book-player.mjs` содержит display state и последовательный проигрыватель.
Он проверяет типы и порядок событий, целочисленные суммы, padded-координаты
и соответствие finalWin/payoutMultiplier до показа первого кадра.
Неизвестное событие вызывает ошибку, а не пропускается.

`web/shared/stage.mjs` визуализирует состояния и управляет эффектами для стенда
и игрового интерфейса. `app.mjs` стенда задаёт QA-контролы и журнал событий.
Множитель принадлежит
ячейке и сохраняется при смене символа. setTotalWin заменяет сумму, не складывает.
Восстановление с заданного индекса сначала проигрывает предыдущие события
без эффектов; браузерное локальное хранилище для финансового состояния не используется.
Новый раунд начинает с чистой карты могил и счётчиков FS.

`fixtures.json` — десять именованных сценариев из `tests/fixtures.json.gz`: выигрыш,
нулевой итог, ретриггер, множитель ×10 и max win для base и bonus. Имена сценариев
описывают контрольный случай целого раунда; некоторые включают бонус даже в base.
Их частота в списке не является вероятностью игры. Обновление:

```sh
python tools/export_animation_fixtures.py
node --test tests/web/book-player.test.mjs
```

## Проверки

Семь автоматических тестов проходят все десять книг и все их точки восстановления.
Проверяются все 12 типов событий, сброс между раундами, сохранение могил,
замена суммы, пропуск эффектов без потери событий, остановка и отклонение
повреждённых/неподдерживаемых книг. Отчёт: `reports/animation-tests.txt`.

Браузерная проверка: `tools/verify_animation_browser.cjs`. При установленном
Playwright и его Chromium можно выполнить её при запущенном локальном сервере:

```sh
node tools/verify_animation_browser.cjs
```

Фактические результаты сохранены в `reports/animation-browser.json`:
1440×1000, 390×844, 480×270, 844×390; по десять сценариев на каждом размере.
После мгновенного проигрывания проверка ждёт декодирования текущих изображений:
даже для предзагруженных файлов смена `src` завершается асинхронно.
Проверяются ошибки JavaScript и HTTP, загрузка изображений, отсутствие
горизонтального переполнения и наложения HUD на барабаны, очистка временных
эффектов, запрет турбо и пропуск к итогу. Отдельный прогон с замедлением CPU ×4
измеряет интервалы requestAnimationFrame. Скриншоты осмотрены локально.

Эмуляция CPU не заменяет физический телефон. Ни RGS, ни лицензированный звук,
ни настоящее восстановление серверной сессии этим этапом не подтверждаются.
